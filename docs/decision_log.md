## 통합 결정 기록 · 2026-11-12

제출 목표: 2026-11-18. 통합 담당으로 사용자 요청 범위에서 A~D 산출물을 연결했다.

1. 원본 저장소 현재 브랜치는 `data/official-claims-v1`, HEAD `d331241`이었다. `main`으로 되돌리거나 데이터 커밋을 다시 적용하지 않았다. 루트 및 상위 bioinfo/etc에서 적용할 AGENTS.md는 발견되지 않았다.
2. 미추적 `api_candidates_*.csv`, `registry_index.csv`, `data/synthetic/`, `scripts/`가 있었다. 원본은 수정하지 않고 `.git`과 모든 작업 파일(.venv 제외)을 outputs 사본으로 보존했다. 사용자 지시가 가이드의 사본 금지보다 우선한다.
3. 사본에서 가이드의 통합 브랜치 `feature/ui`를 생성했다. 원본 작업 상태를 커밋/병합/푸시하지 않았다. 원격 fetch나 Drive 변경도 하지 않았으므로 기준은 작업 시작 시 로컬 상태다.
4. 앱의 단일 데이터는 저장소 CSV 24개·125행이다. XLSX와 제품 ID/이름/신고번호 및 기능성 문구가 일치했다. 실제 읽은 두 파일의 기존 확인일은 모두 11/10이었다. 출처 기록에 적힌 24개 전체 11/11 대조일로 checked_at을 통일했다. 11/12 재검수로 주장하지 않는다.
5. 출처 기록의 '후보 전체 데이터 앱 미사용' 원칙을 제한적으로 확장했다. `registry_index.csv`는 후보 목록만 제공하며 공식 기능성 비교에는 사용하지 않는다. 원료용 표시 행은 제외하지만 목록의 모든 완제품/수출용 여부를 새로 검수한 것은 아니다.
6. 사용자가 제품명·업체명·신고번호로 확정하기 전 자동 Top-1 비교를 금지했다. 공통 API 상태 enum을 유지하고 `selection_required`와 후보 필드를 추가했다.
7. 부정 표현, 100%, 완전/하루 만에/확 좋아짐, 치료·약 대체·체험담 태그가 있으면 유사도에 관계없이 검토 상태로 보낸다. 태그는 표현 점검용이고 법적/의학적 판정이 아니다. 부정의 범위, 인용, 이중부정은 완전한 의미 분석을 하지 못한다.
8. 기존 C의 `치료/예방/완치` 개별 태그는 D의 `질병 예방·치료`로 묶었다. `약대신`은 `약 대체`로 맞췄다. T13/T14는 `과장`을 보완했다. T11은 기대 `혈관 청소·과장`에 `과장` 태그도 추가된다. 검증은 기대 태그 포함 여부이며 실제 전체 태그도 남긴다.
9. EasyOCR를 채택했다. import/모델 초기화를 지연하고 예외·빈 인식 결과를 직접 입력으로 복구한다. 실행 중 모델 다운로드는 금지하고 최초 준비 스크립트에서만 내려받는다.
10. 실제 검증은 Windows Python 3.13.14 CPU다. 3.11은 없었고 버전별 새 환경 검증은 미완료다. 현재 venv는 기존 설치를 재사용했다. 다른 PC는 README대로 독립 venv를 만들어 확인해야 한다.
11. 카카오톡·영상 분석은 구현하지 않았다. 사람 대상 사용성 평가·시연 영상 녹화·최종 제출은 팀 일정으로 남긴다.
12. 확인할 표현에 탐지 문구를 함께 표시하고, 새 이미지/문구/제품 선택 시 이전 결과를 지우도록 했다. 서버 재시작 후 최종 화면을 확인한다.
13. 사용자 요청으로 기본 Streamlit 화면을 재디자인했다. 크림색·녹색 테마, 입력/제품/결과 카드, 18~19px 본문·입력 글씨, 2열 비교를 사용한다. 기본 구조 재배치 후 12개 회귀 시험과 실제 브라우저 비교를 재확인했다.
14. 사용자 요청으로 통합판을 원래 etc/bioinfo/senior-health-claim-checker 저장소로 가져왔다. 원본 미추적 13개 파일의 해시 일치 확인 후 stash 백업, 로컬 feature/ui 브랜치 가져오기, OCR 모델 복사 및 기존 venv 설정 백업 후 전역 OCR 패키지 재사용을 적용했다. 이후 작업·실행은 원본 경로를 기준으로 한다.
