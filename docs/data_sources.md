# 자료 출처 기록

## 2026-11-12 통합판의 적용 범위

- 아래 기존 기록은 보존한다. 앱의 공식 데이터는 `data/processed/official_products.csv` 및 `official_claims.csv` 한 벌이다.
- 아래 '상세 페이지 대조 결과'의 24개 전체 확인일(2026-11-11)을 두 CSV의 checked_at에 반영했다. 수집일 11/10과 대조일 11/11을 구별한다. 통합 당일 실시간 재조회한 날짜는 아니다.
- XLSX와 제품 ID·제품명·신고번호·기능성 원문을 대조해 일치함을 확인했다. 쉬운 설명은 계속 검수 전 초안이다.
- 아래 '후보 전체 데이터는 앱에 사용하지 않음'은 통합판에서 후보 검색에 한해 확장했다. `registry_index.csv`는 신고 목록 후보로만 표시하며 공식 기능성 문구로 사용하지 않는다. 원료용 표시 행은 제외한다.
- 신고 목록의 상세 출처 URL·확인일은 입력 자료에 없다. 미기록 상태를 표시하고 일반 식품안전나라 검색 링크를 별도로 제공한다. 일반 검색 링크를 제품별 검증 출처처럼 표시하지 않는다.

## 기존 팀 기록

- 주 출처: 식품안전나라 건강기능식품 제품 상세 페이지 (https://www.foodsafetykorea.go.kr)
- 수집일(checked_at): 2026-11-10
- 수집 기준: 완제품만(원료용·수출용 제외), 상세 URL이 있는 제품만. 제품 24개(P001~P024), 기능성 표시 125행
- 후보 출처: 식품안전나라 Open API(I0030)로 팀장이 받은 후보 CSV(`api_candidates_*.csv`) 중 24개를 역할 A가 골라 시트로 정리
- 정리 방식: A의 구글 시트(`official_products`, `official_claims`)를 기준으로, 기능성 문구를 성분별 1행으로 나누고 잘리거나 빠진 문구(P002, P009, P014, P017, P023, P024)는 후보 CSV의 전체 문구로 채움
- 쉬운 설명(easy_explanation)은 팀(팀장+Claude)이 쓴 설명이지 공식 문구가 아님. 현재 125행 모두 **초안**이며 팀 검수 전. 앱에는 "공식 문구"와 구분해서 표시할 것. 규칙: 공식 문구에 없는 효능을 덧붙이지 않고, "필요"와 "도움을 줄 수 있음"의 강도를 그대로 유지
- 성분 칸(ingredient)이 비어 있는 행은 원문에 성분명이 없어서 추측하지 않고 비워 둠(P009, P016, P018, P021, P022, P024)
- P024는 상세 페이지에서 문구가 빈 줄로 나뉜 두 줄(①간 건강 / 유산균 증식 등)이라 2행으로 나눔. 성분명 소제목은 없음
- P010 제품명은 상세 페이지 표기("코엔자임Q10 플러스 리포좀비타민C")를 따름. 후보 CSV에는 앞에 "유한"이 붙어 있었음
- P022는 상세 페이지에 같은 문구 블록이 두 번 반복돼 있음(우리 CSV에는 한 번만 기록)
- 후보 전체 데이터(약 4만 6천 건)는 검수하지 않았으며 앱에 사용하지 않음
- 조회 시점에 따라 내용이 바뀔 수 있어 checked_at을 기록함

## 성분 칸이 빈 제품(P009, P016, P018, P021, P022, P024)

- P009 상세 페이지를 확인한 결과, 기능성 내용이 성분명 없이 빈 줄로 나뉜 덩어리로만 표시됨(원문 구조가 그러함)
- 성분명은 문구 내용으로 짐작할 수는 있으나 원문에 없으므로 추측해서 채우지 않음
- 앱에서는 이 행들을 성분 없이 문구만 보여 주거나, 팀이 성분명을 따로 확인해 채울 것
