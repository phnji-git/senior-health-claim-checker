## 1. 목표와 원칙

**대상 사용자:** 건강기능식품 광고를 보고 "이게 공식 표시와 같은 말인가?"를 확인하려는 일반 소비자, 특히 부모님 세대 대신 확인해 주는 가족. 그래서 큰 글씨, 단순한 화면. (팀에서 한 번 확인할 것)

**만들 것:** 광고 캡처 업로드 → OCR 문구(사용자가 수정) → 제품 후보 선택 → 식약처 공식 기능성 표시와 나란히 비교 → 출처 링크·확인일. 한 대의 PC에서 `localhost:8501`로 끝까지 시연한다.

**지킬 것:**
- "진짜/가짜", "불법/사기"를 판정하지 않는다. 제품을 특정 못 하면 확인을 보류한다.
- 공식 문구와 팀이 쓴 쉬운 설명은 구분한다.
- 개인 복용량 추천, 약 복용 변경 지시 금지.
- 모든 결과에 출처 링크와 확인일.

**제출물:** 실행 가능한 앱+README / CSV와 출처 기록 / 20개 시험 결과표 / 시연 영상(2분 내) / 프로젝트 보고서.

## 2. AI 사용 규칙 (모두 공통)

1. 자기 카드의 **요청문**을 본인 AI에 붙여 넣고 시작한다.
2. AI가 만든 코드는 **직접 실행**해서 확인한 뒤 올린다. "됐다고 하더라"는 완료가 아니다.
3. **자기 파일만** 수정한다. 남의 파일을 고치고 싶으면 그 담당에게 말한다.
4. API 키·개인 사진·실제 가족 캡처를 AI 채팅이나 GitHub에 붙이지 않는다.
5. 막히면 30분 안에 팀 채팅에 에러 전문을 올린다. 혼자 붙잡지 않는다.

### 3.2 CSV 열 (이 이름으로 통일)

| 파일 | 한 행 | 열 |
|---|---|---|
| official_products.csv | 제품 1개 | product_id, product_name, manufacturer, report_number, product_type, source_url, checked_at |
| official_claims.csv | 기능성 표시 1개 | product_id, ingredient, official_claim, easy_explanation, source_url, checked_at |
| synthetic_cases.csv | 시험 문구 1개 | case_id, group, ad_text, expected_status, expected_product_id, expected_tag, expected_source, case_type |
| docs/test_results.csv | 시험 결과 1개 | case_id, actual_status, actual_product_id, actual_tag, pass, notes |

- `case_type`은 항상 `synthetic_example` (실제 광고 인용이 아님을 표시).
- `official_claim`은 공식 원문 그대로, 쉬운 설명은 `easy_explanation`에 따로.
- `group`은 `close`(공식과 가까움) / `stronger`(표현이 더 강함) / `treatment`(치료·약 대체) / `uncertain`(불확실).
- `pass`는 예상과 실제 화면이 맞을 때만 TRUE.

### 3.3 자료 출처
- 주 출처: 식품안전나라 건강기능식품 검색의 제품 상세 페이지. 완제품인지(원료용·수출용 제외) 확인하고 URL·확인일을 기록한다. 전체 수집은 하지 않는다.
- 공공데이터포털 API(`getHtfsList01`, `getHtfsItem01`)는 시간이 남을 때만. 키는 채팅·GitHub에 붙이지 않는다.

## 4. 앱 구조

### 4.1 공통 함수 (C 담당, 팀장이 화면에서 호출)
`analyze_claim(ad_text, product_id=None)` → 아래 형식의 dict.

```
{
 "status": "matched | needs_review | no_product | no_official_data",
 "ad_text": "인식했거나 사용자가 고친 문장",
 "product_candidates": [],
 "official_claims": [],
 "review_tags": [],
 "difference_note": "공식 문구와 비교한 요약",
 "source_url": "식품안전나라 제품 상세 URL",
 "checked_at": "YYYY-MM-DD"
}
```
이 형식은 **11/12에 고정**한다. 바꿀 일이 생기면 팀장 승인.

### 4.2 화면 흐름 (팀장)
1. JPG/PNG 업로드, 미리보기.
2. OCR 문구를 수정 가능한 텍스트 상자에 표시. "이 문구로 제품 찾기" 버튼.
3. 후보가 여럿이면 사용자가 선택. 제품명·업체명·신고번호를 다시 보여준다.
4. 결과: 광고 문구 / 공식 기능성 표시 / 점검 표현 태그 / 차이 설명 / 출처 링크·확인일.
5. OCR이 안 읽히거나 제품이 없어도 에러·빈 화면 대신 아래 안전 문구를 보여준다.

### 4.3 비교 규칙
- `완치`, `치료`, `약 대신`, `100%`, `혈관 청소`, `무조건` 등 과장 표현 후보를 **태그로만** 표시한다. 단어가 있다고 위법이라 하지 않는다.
- 유사도 점수는 제품 동일성의 증거가 아니다.

### 4.4 안전 문구

| 상황 | 문구 |
|---|---|
| 확인됨 | 선택한 제품의 공식 표시에서 아래 기능성 내용을 확인했습니다. 광고 문구와 공식 표현을 함께 살펴보세요. |
| 표현이 다름 | 광고 문구는 공식 제품 표시보다 강하게 표현되어 있습니다. 이 비교만으로 위법 여부를 판단할 수는 없습니다. |
| 제품 못 찾음 | 제품을 특정하지 못해 공식 표시를 비교하지 못했습니다. 제품명이나 품목 신고번호를 확인해 주세요. |
| 공식 문구 못 찾음 | 현재 자료에서 관련 공식 문구를 찾지 못했습니다. 미검색은 불법 판정이 아닙니다. |
| OCR 불확실 | 사진에서 글자를 정확히 읽지 못했습니다. 문구를 고치거나 제품명을 직접 입력해 주세요. |

## 5. 환경 설치 (각자 1회, Windows, Python 3.11, CPU만)

프로젝트 폴더에서 PowerShell로 한 줄씩 실행한다. 활성화가 막히면 실행 정책을 바꾸지 말고 아래처럼 `.venv` 안의 Python을 직접 부른다.

```
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

- 기본 `requirements.txt`(streamlit, pandas, rapidfuzz, pillow, pytest)는 **팀장이 첫날 올린다.** 제목만 뜨는 `app.py`로 환경부터 확인한다.
- **OCR 담당만** 추가로 설치한다: `.\.venv\Scripts\python.exe -m pip install paddlepaddle paddleocr`. 샘플 이미지 한 장에서 한글 문구가 출력되는 것을 확인한 뒤 `requirements.txt`에 해당 버전 줄을 추가한다. 그 전까지 나머지 팀원은 OCR 없이 진행한다.
- OCR 설치가 30분 넘게 막히면 즉시 팀장에게 알린다. 앱은 직접 문구 입력으로 계속 만들고, OCR은 `src/ocr.py` 뒤에 격리되어 있어 다른 작업이 멈추지 않는다. PaddleOCR 2.x와 3.x 예제를 섞지 않는다.
- 카카오 모의 연동을 할 때만 `fastapi uvicorn`을 추가한다.

## 6. 카카오톡 (선택, 기본 OFF)

- 실연동에는 비즈니스 계정·채널, 이미지 보안전송 플러그인, 공개 HTTPS 서버, 5초 내 응답이 모두 필요하다. `localhost`는 쓸 수 없다.
- **11/10 저녁에 팀장이 판단한다.** 하나라도 준비가 안 되면 "연동 안 함"이 기본이고, 발표에서 그 이유를 정확히 말한다.
- 나머지 기능이 끝난 뒤 여유가 있으면 모의 payload → FastAPI(`/health`, `/kakao/skill`) → 공통 분석 결과 JSON까지만 AI에 맡겨 만든다. 이미지·URL·사용자 식별값은 로그에 저장하지 않는다.

## 8. 시험과 제출 전 점검

### 8.1 20개 시험 문구
| 묶음(group) | 개수 | 기대 |
|---|---|---|
| close | 5 | 제품 식별 후 공식 문구·출처 표시 |
| stronger | 5 | 위법 단정 없이 공식 표시와 다른 점 설명 |
| treatment | 5 | 점검 태그와 주의 안내, 복용 추천 없음 |
| uncertain | 5 | 제품 없음·오인식·범위 밖·출처 누락 → 보류/수정 요청 |

제품 매칭 Top-1 비율은 제품을 찾도록 설계한 케이스에서만 계산하고, OCR 실패 케이스는 섞지 않는다.

### 8.2 사용성 확인
- "이 제품이 진짜인지 맞혀 보세요"라고 묻지 않는다. "광고 문구와 공식 표시가 어디서 다른지, 출처 링크가 어디 있는지 찾아 주세요"라고 요청한다.
- 팀 밖 5명, 30초 이내에 두 정보를 찾는지, 어디서 막혔는지 기록. 이름·화면 녹화·개인정보는 수집하지 않는다.
- "5명 중 몇 명이 찾음 + 주로 막힌 위치"로만 보고한다. 이 수치는 광고 판정 정확도가 아니다.

### 8.3 제출 전 체크 (팀장)
- [ ] Python 3.11에서 README대로 실행된다.
- [ ] JPG/PNG 업로드 후 OCR 문구를 고칠 수 있다.
- [ ] 제품 선택 후 공식 문구·원문 링크·확인일이 보인다.
- [ ] no product / OCR 불확실 / 공식 자료 없음 세 실패 흐름이 각각 보인다.
- [ ] 모든 가상 광고가 `synthetic_example`로 표시되어 있다.
- [ ] "AI가 사기 판정"이라는 표현이 코드·화면 어디에도 없다.
- [ ] 실제 측정값과 개발 목표가 구분되어 있다.
- [ ] `.env`, API 키, 개인정보가 저장소에 없다.
- [ ] 카카오 연동 여부와 안 한 이유가 발표 자료에 정확히 적혀 있다.
